# Time Tracker

Простое веб-приложение для учёта рабочего времени сотрудников: сотрудники, таймеры с описанием задачи, редактирование записей и отчёт за период.

Стек: Python 3.9+, FastAPI, SQLite, статический UI на HTML/CSS/JS.

## Запуск

```bash
git clone https://github.com/Vonckad/time-tracker.git
cd time-tracker
./run.sh
```

`run.sh` создаёт виртуальное окружение `.venv` (если его нет), ставит/обновляет зависимости из `requirements.txt` и поднимает сервер на http://127.0.0.1:8765.
При первом запуске база `time_tracker.db` заполняется демо-сотрудниками; старая база мигрирует автоматически.

Документация API (Swagger): http://127.0.0.1:8765/docs

Тесты:

```bash
.venv/bin/pytest -q
```

1. Сначала составили `PRD`, прописали корнер кейсы.
2. «Сделай веб-приложение для учёта времени сотрудников: список сотрудников, запуск/остановка таймера с описанием задачи, редактирование записей, отчёт за период. Опубликуй в github.com/Vonckad с историей коммитов».
3. «На Python 3.9 падает `TypeError` при запуске (`str | None`)» — с приложенным трейсбеком.
4. «Добавь пустой favicon».
5. «Объедини блоки сотрудники и таймер и выводи текущее время таймера у каждого. При запуске таймера — модальное окно с описанием задачи, кнопка Старт выключена, пока описание пустое. Пагинация 10/20/50. Кнопка редактирования: появляется Удалить, кнопки таймера скрываются, можно менять сотрудников местами; при удалении таймер останавливается».
6. «Не должно быть ошибок вида `[{"type":"string_too_short","loc":["body","description"],...}]`, ошибки надо сделать на русском».

## Найденные и исправленные ошибки

1. **Падение на Python 3.9.** В моделях использовался синтаксис `str | None`, который поддерживается только с Python 3.10 — на 3.9 приложение падало с `TypeError` при старте. Исправлено: аннотации переведены на `Optional[...]`, добавлен `eval_type_backport` для pydantic, а `run.sh` теперь всегда доустанавливает зависимости (иначе в уже существующем `.venv` новые пакеты не появлялись).
2. **Сырые ошибки валидации в UI.** При пустом описании задачи API отдавал внутренний JSON pydantic (`string_too_short`, `loc`, `ctx`), и он показывался пользователю как есть. Исправлено: добавлены обработчики ошибок, все ошибки API (валидация, 404, конфликты) возвращаются одной понятной строкой на русском в поле `detail`; плюс кнопка «Старт» неактивна, пока описание пустое (пробелы не считаются).
3. **Устаревший `@app.on_event("startup")`.** FastAPI выдавал предупреждения об устаревшем API. Инициализация БД перенесена в `lifespan`.
4. **404 на `/favicon.ico` и `apple-touch-icon`.** Браузер при каждом заходе получал 404 в логах и консоли. Добавлена пустая иконка в `index.html`, эти пути отдают 204.
5. **Таймер при удалении сотрудника.** Чтобы не оставалось «висящих» активных таймеров у удалённых сотрудников, удаление сначала останавливает идущий таймер. Ограничение «один активный таймер на сотрудника» гарантируется уникальным индексом в SQLite и покрыто тестами.
